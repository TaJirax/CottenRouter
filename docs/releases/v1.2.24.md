# CottenRouter v1.2.24

This release expands connection regression coverage after the long-uptime
cleanup repair. Sustained uploads and sustained downloads now both verify that
traffic in either direction keeps the shared TLS relay alive. Quiet and blocked
relays still expire and release their connection slots.

The existing `tls_idle_timeout_ms` setting defaults to 900000 (15 minutes).
Connections silent in both directions for that limit close and must reconnect;
increase the setting when an application needs a longer completely idle relay.

Update CottenDNS clients and servers to the latest published release as well.
The follow-up CottenDNS fixes preserve the embedded server's 15-second UDP proxy
setup budget and isolate DNS cache/pending entries by DNSSEC and EDNS policy.
Router-managed backends use `sudo cottenrouter update --project cottendns`.
Applications embedding the engine, including Panel, require their own rebuilt
release. Router resolves the published CottenDNS and Panel versions independently.

Validation includes the full Linux race suite, repeated idle/connection-slot and
backend recovery checks, uninstrumented routing compatibility/throughput checks,
vet and installer checks. Native Normal and CottenMax clients were exercised
through Router and Panel over UDP and TCP, including slow readers, aborted
transfers and UDP idle expiry/reopening. This is local validation, not a live
multi-day production soak.
