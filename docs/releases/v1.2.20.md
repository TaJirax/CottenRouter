# CottenRouter v1.2.20

CottenDNS installation and independent updates now require a server advertising
Normal, CottenMax, shared credentials and both UDP/TCP DNS. The installed binary
must also report the exact latest release resolved for that operation. An old
normal-only server cannot be announced as Max-ready.

The managed installer identifies Router ownership so standalone updates cannot
accidentally reclaim public port 53. CottenDNS stages and validates its candidate
before stopping the existing service, preserves administrator service drop-ins,
and restores the previous unit, configuration and overwritten binary on failure.
An administrator ExecStart override requires review before automatic replacement.

CottenMax stays inside the CottenDNS backend. Clients select Normal or Max with
the same domain and key. The opt-in expanded capacity setting remains available
in the TUI and CLI; quotas, rates and explicit higher limits remain preserved.

Validation: complete Router tests and vet, successful Router CI and Soar routing
integration, plus an isolated Ubuntu 24.04/systemd installation using the actual
CottenDNS release packages. Normal/Max/Normal mode switching delivered identical
64 KiB payloads over UDP and TCP DNS. Tests also verified stale-release rejection
without a restart and preservation of the existing configuration, key and
administrator drop-ins. Desktop and Android builds remain debug beta artifacts.
